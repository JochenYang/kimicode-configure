# 交付前检查

## 断言的对象

逐项检查：

- 测试层：断言所在的层，是否是真实主张所在的层。
- 断言强度：主张为假时，这条断言是否会失败。
- 环境与数据：是否与目标环境、真实数据形态一致。
- 运行范围：跑的是否是本次改动实际影响的范围。
- 失败路径：关键失败路径是否覆盖。
- 偶发性：通过是否稳定，是否依赖执行顺序或时序。
- 模拟替代真实：mock 或替身通过，真实依赖、序列化与网络边界仍可能失败；在离真实最近的边界增加检查。
- 日志语义：日志来自其他进程、其他请求或更早的执行；要关联请求、时间、进程与实际变化路径。
- 指标定义：结论里的“更快”“更省”要给出基线、样本量与分位数，不给出没有定义的比较。
- 采集通道：优先取最接近用户或系统的观测通道，并标注残余偏差。
- 手工演示：手工操作通过不能替代同一条路径的脚本化复现。

## 辅助信号

覆盖率、类型检查、lint、mock 只是辅助信号，不能替代针对真实主张的断言。

禁止为了让测试通过而伪造结果或伪造执行记录；用于模拟外部依赖的测试替身不在此列。

## 测试写法

测试用行为描述命名，结构遵循 Arrange、Act、Assert（当项目包含自动化测试时）。

## Bugfix

关键测试不能运行，或高风险路径未覆盖时，交付须明确升级说明。
