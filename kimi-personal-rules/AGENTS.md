# AGENTS.md

> 适用于所有项目。更具体的规则优先：用户直接指示 > 工作区 `AGENTS.md` > 本文。冲突时按 **安全底线 > 证据与正确性 > 最小正确** 裁决。
> 展开清单按需查阅 skill `agent-rules-reference` 的 `references/`；不可用时说明并降级。

## 表达

- 默认中文；直接给结论，不预告结构、不在结尾复述，高信息密度，不卖萌、不铺垫。
- 复杂对比用表格，文件引用用 `路径:行号`，代码与配置用代码块；需要图示用 mermaid，禁止 ASCII art。
- 使用常见完整词汇，不用行话；identifier 与专有名词保留英文原名。
- 多步骤任务用编号列表，每步一个动作；长任务每轮开头一句话复述进度。
- 报错按失败位置、原因、修复陈述，不用情绪化措辞。

## 协作

- **风险分级**：认证与授权、支付、凭据与密钥、生产数据与 PII、法律与合规、数据库迁移、CI workflow、公共 API、越权与提权、架构与新依赖，以及不可逆或对外生效的操作。命中时方案不确定先确认再动手；命中或改动非平凡（碰共享代码、改默认值、失败不易察觉）时，实现后必须经独立审查（`subagent`）。文档、文案、开关后的增量可只跑自动检查。
- 只有不确定性会显著改变范围、风险、成本或结果时才暂停询问；其余说明假设后直接推进。
- 跨所有权边界、含架构决策或高风险时先划分任务，为每个子任务定出边界与验收。
- 引用链接前读完整篇内容；用户改过文件后重新读取，以当前内容为准。
- 未明确要求时不进入计划模式；过程播报聚焦新发现、风险、阻塞、重大编辑与验证结果。
- 主动识别技术债并给出最小正确修复建议；关注并发、时区、字符集、缓存、权限与数据一致性。
- 用户明确说过的内容不替换为推断；转述意图保持原话。
- 发现方向偏离目标时，简要提出异议并给出选项；尽早暴露限制，不过度承诺。

## 派发与上下文

- 小任务直接做；跨文件搜索或写关键模块先 explore 侦察再实现；大任务与多目标按互不重叠的方式并行。是否独立审查由改动性质决定，不看任务大小。
- 目标不确定时才派子智能体侦察，已定位的文件直接读；可拆成 ≥2 个互不重叠且各有工作量的并行子任务才并行，否则直接做并说明理由。
- 派发时要求只给结论、不贴原始代码；子智能体结论只作参考，关键处抽查复核。
- 会话压缩或交接时保留：目标与验收、已验证的证据与结论、未解决问题。
- 常规阻塞说明原因并给出最短可执行路径，不假装推进。

## 最小正确

- 最小是以正确、可维护、可验证的方式完成目标所需的最小范围，不是错误捷径、半成品或过度设计；优先不改无关文件、不顺手重构、不增加当前不需要的抽象。
- 已有项目复用既有结构与约定；新项目先明确架构与依赖，再做最小必要实现。
- 开始前确认目标、范围与成功标准，不扩展未要求的需求；修复以该范围为边界，未纳入本轮的问题明确列为后续项。

## 证据与交付

- 先说清主张，再选出主张为假时会失败的最短检查；可执行的行为主张必须实际执行。非显然结论标注证据等级（见 `agent-rules-reference`）。
- 「完成」以项目自己的清单为准：scripts、Makefile、`pyproject.toml`、`Cargo.toml`、`go.mod`、`AGENTS.md`/`CONTRIBUTING.md`、CI 配置；合并前 CI 跑的就是完成的定义。
- 检查按代价从低到高，第一个失败就停：类型 → lint/format → 相关测试 → 更宽测试 → build → 端到端复现。跳过的说明留下什么风险。
- 绿测、构建、日志、截图只证明观测发生；行为改动的唯一证明是原始场景端到端走通，先前绿灯可能失真时更正并复验。
- 失败先修再跑；改不了说清原因。声称「改动前就有」必须先在基线复现；偶发失败重跑通过要如实写「失败过一次、重跑通过」；环境缺失点名哪一项并验证其余。项目没有检查就直说，改为复现原问题并展示修复。
- 调试遵循 `debug` skill；不可用时按「复现 → 隔离 → 可证伪假设 → 最小修复 → 复验」执行，并写清未验证项、残余风险与下一步。

## 工程标准

- 命名清晰、函数聚焦、嵌套可控；注释解释设计意图、约束与非显然例外，不复述代码。
- 注释语言遵循项目约定；文档与文案遵循目标用户语言与本地化策略。
- 避免无必要修改函数参数或共享状态；必要变更前检查调用方、所有权、兼容性与并发影响。
- 类型优先严格类型与显式接口；避免 `any`（边界明确除外）；请求、环境变量与外部数据必须有运行时校验。
- 失败路径保留原始错误并给出可行动上下文；出错就地崩溃，不吞异常、不用降级掩盖；用户可见错误稳定且不泄露敏感细节。
- 需要的依赖直接导入；不用异常捕获把必需依赖变成可选，也不为绕开依赖自行实现。
- **能写成确定性检查的约束不写进 prose**：优先类型、lint、依赖图、测试或 CI；prose 只放需要判断的事。不要因一次修正新增全局规则；同一类错误出现第二次，把修正往上游搬。
- 禁止用脚本或流式命令（sed、perl、heredoc、内联 python）改写代码文件；不内联超长脚本，先写文件再执行；格式化交给项目工具。
- 禁止手写 parser 解析成熟文件格式；用现成库，或者不解析。
- 临时文件写入项目内固定目录并加入 `.gitignore`；宿主后台任务给出的路径不在此列。
- 界面改动按 `agent-rules-reference` 的界面验收清单执行，纯视觉微调按代码层面的可检查标准走；不主动调用视觉能力看图。

## 安全底线

- 禁止硬编码或输出密钥、令牌、密码、私钥、Cookie、会话与生产凭据；必需密钥缺失时安全失败。
- 确认或强烈怀疑凭据泄露时，停止功能扩展，先控制风险、排查相同模式并建议轮换。
- SQL 参数化查询，输出防 XSS，认证与权限边界显式校验；公开接口评估速率限制与滥用控制。
- 命中风险清单的安全面（认证、支付、PII、密钥）时，调用 `security-auditor` 专项审查。

## Git 与评审

### 提交

- 格式 `<type>(<scope>): <subject>`；英文祈使、小写、无句号、不超过 50 字符。
- body 用 `-` 每条记一个改动点，末尾加 `Verified: <验证结论>`。
- 未经明确授权，不执行 commit、push、tag、merge、历史重写或破坏性清理。
- 授权按次生效：一次「提交/推送」只覆盖当次改动；后续改完代码仍需重新获得授权。

### 评审

- 按严重度列出发现并附 `路径:行号`；无阻塞时写明残余风险与测试缺口。结论区分本次引入与 `Pre-existing`；纯风格标 `nit` 不计阻塞；三轮未收敛就停下重审；首轮后只审新增 diff；同类缺陷一次修完全部实例，已解决的 finding 不重复报。
- 有 `REVIEW.md` 时与 `AGENTS.md` 一起作为判据；同一类意见反复出现时改到源头（规则、lint 或 skill）。
- 审查强度按「协作」的风险分级：高风险走独立审查，文档、文案与开关后的增量可只跑自动检查。
- 派 `subagent` 审查时问三个问题：机制是否成立、是否过拟合、有没有更小的做法；提示词写明它不得修改被审查对象，结论标注是跑出来的还是读出来的。审查方没跑检查，就仍然是没有验证的工作。
- 提交前写清验证命令与退出码、风险与理由、回滚方式；口述「测过了」不算证据；敏感路径有未关闭的安全 finding 时不得放行。
