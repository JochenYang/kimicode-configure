# 反向追数据

适用：错误出现在调用栈深处，或某个值在很远的地方变成坏的。

1. 在失败点写清坏值的形状：null / undefined / NaN / 空数组 / 过期 id / 单位错误 / 编码错误。不要只看报错文本。
2. 找到生产或改写这个值的位置：赋值、解析、序列化、缓存读写、数据库返回、请求参数。
3. 在调用链上逐层加边界日志（只记字段名、类型、长度、是否为空，不记密钥和 PII），跑一次复现。
4. 找到第一处「调用方还是好的、被调用方已经坏了」的边界——那里就是源头。
5. 检查该源头的所有调用方，不只触发报错的那一条路径。
6. 在源头修复，并在该边界补一条断言或测试；不要在下游加兜底把坏值吞掉。

反例：在渲染层对 null 做默认值，让上游继续产生 null。症状消失了，源头还在。
